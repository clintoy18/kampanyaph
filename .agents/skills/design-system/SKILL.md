---
name: design-system
description: Reusable visual foundations and component consistency
---

Define semantic design tokens for surface, text, border, accent, focus, danger, success; spacing, radii, typography, and responsive breakpoints. Use a small component inventory: buttons, fields, selects, dialogs, tables, status chips, editor toolbar, side navigation, calendar cells, empty/error states. Document variants, hover/focus/disabled/loading, and density. Choose a deliberate visual identity with owner approval; do not hardcode arbitrary one-off styling. Support dark mode only if approved; do not add it by default. Audit components for consistency before creating new variants.
